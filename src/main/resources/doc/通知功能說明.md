# 通知功能說明

## 功能概述

通知系統提供**站內通知**功能，未來可擴展為 Email 通知。

### 目前實現
✅ **站內通知（Notification）**
- 儲存在資料庫
- 使用者可透過 API 查看
- 支援已讀/未讀狀態

### 未來擴展
🔜 **Email 通知**
- 使用 Spring Mail + SMTP
- 或使用第三方服務（SendGrid, AWS SES）

## 通知類型

| 類型 | 說明 | 觸發時機 |
|------|------|---------|
| `WELCOME` | 歡迎訊息 | 註冊成功（待實現） |
| `RESERVE_SUCCESS` | 預約成功 | 成功預約書籍副本 |
| `RESERVE_AVAILABLE` | 預約書籍可取書 | 書籍歸還，輪到使用者取書 |
| `RESERVE_EXPIRING` | 預約已過期 | 超過取書期限未取 |
| `LOAN_DUE` | 借閱即將到期 | 到期日前3天（排程任務） |
| `PENALTY` | 違規處罰通知 | 逾期產生違規點數或停權 |

## 資料庫結構

```sql
CREATE TABLE notification (
    id BIGINT PRIMARY KEY,
    user_id BIGINT NOT NULL,           -- 接收通知的使用者
    type ENUM(...) NOT NULL,            -- 通知類型
    title VARCHAR(200) NOT NULL,        -- 標題
    content TEXT NOT NULL,              -- 內容
    is_read TINYINT(1) DEFAULT 0,      -- 是否已讀
    related_id BIGINT,                  -- 相關ID（備用）
    reference_id BIGINT,                -- 關聯記錄ID
    reference_type ENUM(...),           -- 關聯類型
    created_at TIMESTAMP                -- 建立時間
);
```

### 2. 標記通知為已讀

**端點**: `PUT /api/notifications/{id}/read`

**權限**: 需登入

**回應**: `"已標記為已讀"`

### 3. 獲取未讀通知數量

**端點**: `GET /api/notifications/unread-count`

**權限**: 需登入

**回應範例**: `5`

**端點**: `PUT /api/notifications/read-all`

**權限**: 需登入

**回應**: `"已全部標記為已讀"`

## 使用範例

### 前端實現 - 通知圖標

```javascript
import { useState, useEffect } from 'react';
import axios from 'axios';

function NotificationBell() {
  const [unreadCount, setUnreadCount] = useState(0);
  const [notifications, setNotifications] = useState([]);
  const [showDropdown, setShowDropdown] = useState(false);

  // 獲取未讀數量
  useEffect(() => {
    fetchUnreadCount();
    // 每30秒輪詢一次
    const interval = setInterval(fetchUnreadCount, 30000);
    return () => clearInterval(interval);
  }, []);

  const fetchUnreadCount = async () => {
    const response = await axios.get('/api/notifications/unread-count');
    setUnreadCount(response.data);
  };

  const fetchNotifications = async () => {
    const response = await axios.get('/api/notifications');
    setNotifications(response.data);
  };

  const markAsRead = async (id) => {
    await axios.put(`/api/notifications/${id}/read`);
    fetchUnreadCount();
    fetchNotifications();
  };

  const markAllAsRead = async () => {
    await axios.put('/api/notifications/read-all');
    fetchUnreadCount();
    fetchNotifications();
  };

  return (
    <div className="notification-bell">
      <button onClick={() => {
        setShowDropdown(!showDropdown);
        if (!showDropdown) fetchNotifications();
      }}>
        🔔
        {unreadCount > 0 && <span className="badge">{unreadCount}</span>}
      </button>

      {showDropdown && (
        <div className="notification-dropdown">
          <div className="header">
            <h3>通知</h3>
            {unreadCount > 0 && (
              <button onClick={markAllAsRead}>全部標為已讀</button>
            )}
          </div>
          
          <div className="list">
            {notifications.map(notif => (
              <div 
                key={notif.id}
                className={notif.isRead ? 'read' : 'unread'}
                onClick={() => markAsRead(notif.id)}
              >
                <h4>{notif.title}</h4>
                <p>{notif.content}</p>
                <small>{new Date(notif.createdAt).toLocaleString()}</small>
              </div>
            ))}
          </div>
        </div>
      )}
    </div>
  );
}
```

## 通知發送時機

### 1. 預約相關
```java
// 預約成功
RESERVE_SUCCESS → 使用者預約書籍副本時

// 書籍可取
RESERVE_AVAILABLE → 書籍歸還，輪到使用者取書時

// 預約過期
RESERVE_EXPIRING → 排程任務檢查，超過取書期限時

// 排隊位置更新
RESERVE_SUCCESS → 有人取消預約，後面的人往前遞補時
```

### 2. 借閱相關
```java
// 即將到期提醒
LOAN_DUE → 排程任務檢查，到期日前3天

// 逾期通知
PENALTY → 排程任務檢查，每日逾期時
```

### 3. 違規處罰
```java
// 違規點數
PENALTY → 歸還逾期書籍時

// 停權通知
PENALTY → 累積10點違規點數時
```

## 排程任務

在 `OverdueCheckScheduler` 中：

```java

}
```

## Email 功能（未來擴展）

### 方案一：Spring Mail + SMTP

```xml
<!-- pom.xml -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-mail</artifactId>
</dependency>
```

```properties
# application.properties
spring.mail.host=smtp.gmail.com
spring.mail.port=587
spring.mail.username=your-email@gmail.com
spring.mail.password=your-app-password
spring.mail.properties.mail.smtp.auth=true
spring.mail.properties.mail.smtp.starttls.enable=true
```

```java
@Async
public void sendEmail(User user, String subject, String content) {
    MimeMessage message = mailSender.createMimeMessage();
    MimeMessageHelper helper = new MimeMessageHelper(message, true);
    
    helper.setTo(user.getEmail());
    helper.setSubject(subject);
    helper.setText(content, true); // true = HTML
    
    mailSender.send(message);
}
```

### 方案二：第三方服務（推薦）

使用 **SendGrid** 或 **AWS SES**
- 更穩定
- 有發送記錄
- 容易擴展

## 注意事項

1. **異步處理**：Email 發送應使用 `@Async` 避免阻塞主流程
2. **失敗處理**：Email 發送失敗不應影響業務邏輯
3. **頻率限制**：避免短時間內發送大量通知
4. **隱私保護**：通知內容不應包含敏感資訊
5. **效能考量**：使用者數量大時考慮使用訊息佇列（RabbitMQ, Kafka）
